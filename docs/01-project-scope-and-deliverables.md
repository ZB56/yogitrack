# Project Scope & Deliverables (course document)

## Objective
This assignment will guide your learning process to ensure you can:
- Implement key use-cases in a web-based application.
- Design and develop a MERN-based full stack application.
- Create document-artifacts for all project phases.

## Scope
The application should be built using the MERN technology stack. It should
implement the requirements documented in PROJECT REQUIREMENTS & USE CASES.

Key activities:
- Design and develop a MERN-based full stack application that implements the
  use-cases specified.
- Implement a CI/CD pipeline to enable incremental delivery.
- Deploy the application on the cloud. The recommended platform is Heroku. It is
  a paid platform, approximately $5.00 per month for a small application.
- Create document-artifacts (e.g. Readme, UML diagrams, and key architecture and
  design decisions) for all project phases from requirement specifications to
  design, implementation, and deployment. You may need to do some research to
  identify and create relevant artifacts to document your application, keeping
  in mind its long term maintenance and enhancements.

Several tools and platforms need to be installed and configured. See
`02-environment-setup.md`.

## Deliverables
Two increments.

### Project Part 1
- Deploy the application on one of:
  - Option 1: zyLabs platform — quick start without setting up Git and Heroku.
  - Option 2: Heroku — requires setting up the complete CI/CD pipeline.
- Project report documenting the key use-cases, design decisions and UML models.
- Due Sunday, Week 4 (11:59 pm CT).

### Project Part 2
- Application deployed on cloud with code repo on GitHub.
- CI/CD pipeline to deploy incremental changes.
- Updated project report.
- Due Friday, Week 8 (11:59 pm CT). Friday, Week 8 is the last day of the course.

### High level grading guideline

**Use cases**
- 100%: Fully and thoughtfully implemented; creative use of technology stack,
  fully leveraging its features; delivering value aligned with the project goal
  and addressing the problem statement.
- 99–85%: Fully and thoughtfully implemented; delivering value aligned with the
  project goal and addressing the problem statement.
- 84–70%: All use cases implemented but a few are incomplete.
- <70%: Several use cases missing and incomplete.

**Tech-stack use**
- 100%: The design leverages the power of the technology stack and demonstrates
  its important features.
- 99–85%: The design uses the technology stack effectively.
- 84–70%: Some features of the stack are used and could be further improved.
- <70%: The application fails to use the power of the technology stack.

**UI Design**
- 100%: Intuitive UI/UX, responsive design, with thoughtful use of frontend tools.
- 99–85%: Effective use of UI tools across all use-cases.
- 84–70%: Some UI aspects could be improved.
- <70%: Significant improvement needed to make UI user-friendly and intuitive.

**Code / GitHub**
- 100%: All submitted code works. All features implemented correctly and
  completely. Code is well commented and follows good coding conventions. Code
  well organized with informative Readme. Regular commits with meaningful messages.
- 99–85%: All submitted code works. Some functionalities, although not critical
  to the overall product, are missing. Code follows best practices but could be
  improved.
- 84–70%: All submitted code works. Several important functionalities are
  missing. Code quality needs improvement.
- <70%: Code does not compile or throws exceptions. Several important
  functionalities missing or broken. Code quality needs significant improvement.

**Project report**
- 100%: All sections complete and correct. High quality work in structure,
  clarity, readability, and presentation.
- 99–85%: All sections complete and correct. Good quality but may miss some
  finer details.
- 84–70%: All sections complete and correct, but lacks clarity and structure.
- <70%: One or more sections incomplete or missing. Several errors.
